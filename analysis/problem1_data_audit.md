上述本地运行没有包含数据处理分支的 CSV，因此脚本的逐字段合并比较未在本机运行；脚本提交到以数据处理分支为基底的审计分支后可直接执行该比较。另通过 GitHub 中当前文件内容完成了独立控制核验：现有单品日表为 46,595 行、246 个单品、无重复“日期×单品”，总销量 471,275.839 kg、总销售额 3,372,023.342 元、交易笔数 878,042、打折笔数 47,362、打折销量 31,753.107 kg，均与从原始附件独立重算的控制数一致。现有品类日表为 6,474 行、6 个品类、无重复“日期×品类”，上述销量、销售额、交易笔数、打折笔数和打折销量控制数也一致。

对两张现有日表逐行复核 `平均零售单价 = 销售额 / 销量`，最大绝对残差为 0；品类日表逐行复核 `打折销量占比 = 打折销量 / 销量`，最大绝对残差也为 0。单品日表缺少 `打折销量占比` 字段，审计脚本的重算输出补充了该字段；这不影响现有销量和金额口径，但会限制后续单品层面的折扣敏感性描述。

## 可用性与建议

现有表的口径说明与本审计的主分析口径一致：使用正常销售、金额/销量构造加权均价、全店无记录日不作为零销量。若脚本在含有既有CSV的分支路径运行，应以自动比较结果判定逐字段是否一致。优先使用重算输出和现有表的比较结果后，再开始问题一 EDA。建议将 `营业日历.csv` 的 `是否营业_有销售` 改名为 `是否有销售记录`，并在后续单品相关性分析设置共同活跃期/共同观测日阈值。
